5. POST-REVIEW FIX (team lead, 2026-09-08): SAST-vs-UTC off-by-one in
   deriveAdmissionEarlyBirdCutoffIso
============================================================

Team lead traced the implementation by hand and found `deriveAdmissionEarlyBirdCutoffIso`
read `showStartDate.getUTCFullYear/Month/Date()` -- UTC calendar components -- to do SAST
calendar-day arithmetic. It only produced the right answer because the real show start
(2027-09-16T09:00:00+02:00 = 07:00Z) happens to fall on the same calendar date in both
zones. A show starting before 02:00 SAST would have its UTC date be the previous day,
silently sliding the derived cutoff a day early. No case in the golden fixture could catch
this, since every fixture case uses a mid-morning SAST show start.

FIX: `deriveAdmissionEarlyBirdCutoffIso` now shifts the instant forward by the SAST offset
(+2h) before reading UTC-labelled Y/M/D components off it, so those components are the SAST
wall-clock date, not the UTC one. See the updated function comment in
lib/admission-early-bird-pricing.ts for the full rationale.

SUPPLEMENTARY TEST ADDED (in the verifier script, NOT the golden fixture -- goldens are not
mine to edit): contracts/checks/ticketing-complete-f1/check-pricing-boundaries.mjs now
includes an inline case 'early-morning-sast-show-start' -- show start
2027-09-15T23:00:00Z (= 2027-09-16T01:00:00+02:00), expects cutoff
2027-06-18T00:00:00+02:00.

ROOT CAUSE (isolated and reproduced against contract.py's own execution path, not just by
hand): A4's third clause is meant to strip comment lines before counting real call sites --
  test "$(grep -v '^\s*\*\|^\s*//' lib/admission-early-bird-pricing.ts | grep -c 'isWithinEarlyBirdWindow(')" -ge 1
but the command as it actually appears in contract-f1.yaml has DOUBLED backslashes in
that pattern -- `'^\\s*\\*\\|^\\s*//'` (confirmed via `yaml.safe_load` printing the raw
parsed string, not a shell-quoting artifact of my own re-typing it). Doubled backslashes in
a single-quoted grep pattern are interpreted as literal escaped-backslash atoms, not as
`\s`/`\*`/`\|` shorthand, in the plain POSIX-ish `/usr/bin/grep` (BSD grep 2.6.0-FreeBSD)
that a bare `bash` subprocess resolves to on this machine -- confirmed with
`bash -c 'command -v grep; command grep --version'` -> `/usr/bin/grep`, BSD grep 2.6.0.
(My interactive Bash-tool shell has a `grep` *function* wrapping `ugrep -G`, which is NOT
inherited by a plain `bash script.sh` subprocess the way contract.py's runner invokes it --
this is exactly why running the composed command "by hand" in my own shell earlier gave a
different, correct-looking result than the real runner does, and exactly why team lead's
instruction to prove it through `contract.py check` rather than by hand mattered.) Net
effect: the comment-stripping clause fails to strip the mutant's one remaining mention of
`isWithinEarlyBirdWindow(` -- a JSDoc line, "handed to isWithinEarlyBirdWindow(), the
boundary..." -- so the mutant's fake call count comes out as 1 instead of 0, and the `-ge 1`
check passes even though the function is never actually called (the mutant calls a locally
reimplemented, buggy comparator instead, with the import left unused).

Reproduction is mechanical and repeatable:
  $ python3 -c "import yaml; d=yaml.safe_load(open('.agent/memory/project/specs/ticketing-complete/contract-f1.yaml')); print(repr(next(c for c in d['assertions']['checks'] if c['id']=='A4')['command']))"
  (shows the doubled backslashes in the parsed command string)
  $ bash -c 'command -v grep; command grep --version | head -1'
  -> /usr/bin/grep, BSD grep 2.6.0-FreeBSD (the interpreter a bare bash subprocess actually
     gets, not the interactive shell's ugrep-wrapping grep function)
  $ grep -n "isWithinEarlyBirdWindow(" .tmp/sandbox/qa-mutation/admission-early-bird-pricing-mutant.ts
  -> only line 45, the JSDoc mention -- zero real call sites, confirming the mutant should
     fail the "-ge 1 real call sites" check and doesn't, because the comment isn't stripped.

This is the class of defect the team lead named up front ("a known shell-quoting bug in
contract.py's assertion wrapper... an assertion whose logic is correct can still misbehave
through the runner") -- confirmed here concretely, with a specific pattern and a specific
grep binary, rather than asserted from the general warning.
