1. Discovery: fabrication lives in Sanity too, not just the static fallback
===========================================================================

lib/data/board.ts and lib/data/societies.ts are only rendered when Sanity
returns no documents for that type. Live query against the dataset showed
Sanity already had boardMember/society documents seeded with the exact same
fabricated names and figures as the code fallback:

the live page, since Sanity (checked first) was the actual source being
rendered. Both were fixed.

8. FOLLOW-UP: fabricated meeting days/times and venues (lib/data/societies.ts)
===========================================================================

Team lead flagged this as more serious than founded/memberCount: a wrong
founding year is a wrong fact; a wrong meeting day/time/venue sends a real
person to a real building on the wrong night. Confirmed invented rather than
sourced against docs/leeann-source/society-website-information-form_2026-09-01.md
(Lee-Ann's intake form asking affiliated societies for exactly this data —
responses not yet back).

Same two-layer defect as before: the fabricated `meet`/`venue` values were
present both in the code fallback (lib/data/societies.ts) AND seeded into the
21 live Sanity society documents (already patched in section 4 for founded/
memberCount, but meets/venue were untouched at that point).

Changes:

- types/index.ts: `Society.meet` and `Society.venue` changed from required
  to optional (`meet?: string; venue?: string;`) — the site can now correctly
  represent "we don't have this yet" instead of always carrying a string.
- lib/data/societies.ts: removed the `meet` and `venue` properties entirely
  from all 21 entries (previously invented values like "2nd Tue, 19h30" /
  "Kirstenbosch Hall, Cape Town"). Header comment added citing the intake
  form and explaining why no replacement value was invented.
- sanity/schemas/documents/society.ts: added `meetPlaceholder` and
  `venuePlaceholder` boolean fields (same pattern as foundedPlaceholder/
  memberCountPlaceholder).
- sanity/queries.ts: `societyListQuery` and `societyBySlugQuery` now also
  fetch `meetPlaceholder`, `venuePlaceholder`.
- components/societies/SocietyCard.tsx: SanitySociety type gains
  `meetPlaceholder?`/`venuePlaceholder?`. Rendering: when `meets`/`venue`
  has a real value, render it as before; when absent AND the placeholder
  flag is set, render a quiet "To be confirmed" badge (border-rule/bg-bone/
  text-muted tokens) in place of the field — no specific invented day, time,
  or address is ever shown. Chose to omit the fabricated string outright
  (per team lead's stated preference) rather than show a "confirmed-looking"
  value with a small disclaimer next to it, since this is the field a
  visitor actually acts on.
- app/(marketing)/societies/page.tsx and [slug]/page.tsx: static-fallback
  mapping sets `meetPlaceholder: true, venuePlaceholder: true` (meet/venue
  are now `undefined` on the source objects); [slug]/page.tsx detail-grid
  rendering gets the same real-value-or-placeholder-badge treatment as the
  card.
- Left untouched, per instruction: society `name`, `region`, `province` —
  these read as genuine South African orchid societies and locations: no
  society name looked invented on inspection.
