9. FOLLOW-UP: Codex GPT-5.5 findings — seed script had zero placeholder
   awareness, and board _id was derived from the name being corrected
===========================================================================

Codex reviewed the integrity diff and returned FAIL on two real defects,
verified by the team lead and confirmed independently here.

Finding 1 — scripts/seed-sanity.ts had zero placeholder awareness
-------------------------------------------------------------------------
`grep -c placeholder scripts/seed-sanity.ts` returned 0 before this fix. The
live documents were patched (sections 3/4/8), but the generator that
recreates them from lib/data/* did not emit any of the placeholder flags —
re-running `pnpm seed` would have silently re-introduced unmarked board
members and society founding-years/member-counts as "confirmed fact" Sanity
documents (with no code-fallback badge, since documents would exist).

Fix — scripts/seed-sanity.ts:
- `mapBoardMembers()` now emits `placeholder: m.name === BOARD_PLACEHOLDER_NAME`.
  `BOARD_PLACEHOLDER_NAME` ('To be confirmed') is exported from
  lib/data/board.ts so the flag is derived from the sentinel, not a second,
  separately-maintained boolean that could drift from the name field.
- `mapSocieties()` now emits `foundedPlaceholder: true`, `memberCountPlaceholder: true`
  unconditionally (the entire static societies array is our own estimate —
  see lib/data/societies.ts header), and `meetPlaceholder: s.meet === undefined`,
  `venuePlaceholder: s.venue === undefined` (derived per-field, so a future
  partial update — e.g. one society supplies a real venue but not a meeting
  time — is handled correctly without a script change). `meets`/`venue` are
  only included in the mapped object when defined, so createOrReplace clears
  any previously-seeded value on re-seed, matching the live "unset" already
  applied in section 8.

Finding 2 — deterministic board _id encoded the fabricated name
-------------------------------------------------------------------------
`scripts/seed-sanity.ts:87` (pre-fix) built
`_id: safeid('boardMember', \`${m.name}-${m.role}\`)`. The 6 documents
patched in section 3 kept their original ids (e.g.
`boardMember-dr-annelie-van-der-merwe-president`), because a Sanity `patch`
only changes fields, never `_id`. Re-running the (then-unfixed) seed script
after the name was corrected to "To be confirmed" would have minted 6 NEW
documents under ids like `boardMember-to-be-confirmed-president`, leaving
the old fabricated-name-id documents in place as orphans — a duplicated
committee, half of it still addressable under ids that encode invented
people.

Fix — `mapBoardMembers()` now keys on role alone: `safeid('boardMember', m.role)`.
Roles (President, Vice-President, Secretary, Treasurer, Chair of Judging,
Editor) are the stable identity; names are the field expected to change
when SAOC supplies the real officeholder, and a role-derived id survives
that edit without minting a new document. Society `_id` (safeid('society',
s.name)) was left unchanged per the team lead's instruction — society names
were not altered by this work, so there is no equivalent churn risk there.
