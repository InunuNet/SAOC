FOLLOW-UP — Codex GPT-5.5 FAIL fix: empty-array-is-truthy
==========================================================

Codex flagged `about?.timelineNodes ? (...)` at about/page.tsx:176 — an empty
array (`[]`) is truthy in JS, so a Sanity field that exists but has been
cleared (`timelineNodes: []`) would render an empty `<PortableText>` block
instead of falling through to the `Timeline` fallback. Team lead asked me to
check the same pattern across both rebuilt pages, not just the cited line,
and to verify by exercising an actual empty array rather than re-reading the
code.

Audit of every CMS-array selector in both files:
  - about/page.tsx: `about?.pillars` (bug), `about?.timelineNodes` (bug —
    Codex's finding).
  - judging/page.tsx: `data?.intro` (bug), `data?.howItWorks` (bug),
    `data?.becomingAJudge` (bug), `data?.stats && data.stats.length > 0`
    (already correct — not a bug), `data?.judges ?? []` (a default, not a
    render-branch selector — not a bug), `data?.showPublicDirectory === true`
    (boolean equality, not a bug).

Fix applied — all five buggy selectors now guard on length:
  - about/page.tsx:126  `about?.pillars && about.pillars.length > 0 ? (`
  - about/page.tsx:176  `about?.timelineNodes && about.timelineNodes.length > 0 ? (`
  - judging/page.tsx:78  `data?.intro && data.intro.length > 0 ? (`
  - judging/page.tsx:116 `data?.howItWorks && data.howItWorks.length > 0 ? (`
  - judging/page.tsx:158 `data?.becomingAJudge && data.becomingAJudge.length > 0 ? (`
