⚠ LIVE SIDE EFFECT — READ BEFORE WRITING AUTOMATED COVERAGE FOR THIS ROUTE ⚠
POST /api/contact sends a real outbound email via Resend on every successful submission
(the confirmation email to the submitter's address) — it is not mocked or gated behind a
test mode. The end-to-end proof below used qa-members-portal-test@example.com, a
non-existent address at a reserved domain (RFC 2606), so Resend was asked to deliver to an
address that will bounce. The route treats email-send failure as non-fatal (the 201 was
genuine and independent of the send outcome), so this is not a defect in the route or in
this feature's implementation — but it means bounces against the sending domain did occur,
which matters more than usual right now because this project is mid-migration on domain +
Resend DNS (see project memory: domain_migration_resend_sequencing). The test document this
created in contactSubmissions (id itObDm976jh2oaHCF26i) has been deleted — see "ROUND 4"
below — but the email attempt itself cannot be recalled.
Implication for F7 (Playwright form coverage): any automated test that POSTs to this route,
or drives the real ContactForm/SuggestionForm UI to submission, will trigger a real send.
Future coverage needs either (a) a test-mode/dry-run guard on POST /api/contact (e.g. skip
the Resend call for an allow-listed test-domain pattern or an explicit header/flag), or
(b) a mocked mailer in the test harness so `sendEmail` is never actually invoked. Do not
add ad hoc automated coverage against this route until one of those exists.
