=== Dev agent: Codex-flagged dead-link fix (fallback event -> 404) — 2026-09-06T21:52:19Z ===

DEFECT (Codex GPT-5.5, confirmed by team lead): getFallbackEventsForSociety() in
app/(marketing)/societies/[slug]/page.tsx built SanityEvent objects with
slug: slugify(title), and SocietyEvents.tsx passed them straight into the shared
EventCard component, which unconditionally links its title to /events/${slug}.
app/(marketing)/events/[slug]/page.tsx has NO static-data fallback — it calls
notFound() for any slug Sanity does not return. So a fallback-origin event card
(the exact case the fallback exists to serve) could link to a route that 404s.

FIX CHOSEN: option (a), surgical, matches "surgical fixes only". getSocietyEvents()
now returns { events, live } — live=false whenever the events came from the
static-data fallback rather than a Sanity hit. SocietyEvents.tsx takes a new `live`
prop: when true, events render via the existing EventCard (unchanged, still used
by app/(marketing)/events/page.tsx too — not touched). When false, events render
via a new local, non-exported FallbackEventRow (defined inside SocietyEvents.tsx)
that is visually consistent with EventCard but has NO <Link>/<a> anywhere — title
is plain text, hostSociety row dropped (redundant on the society's own page
anyway), venue kept as plain text. A fallback-origin card can now structurally
never emit a link to a route that might not exist — this isn't dependent on
which slugs happen to coincide with Sanity docs.

Files changed: app/(marketing)/societies/[slug]/page.tsx, components/societies/SocietyEvents.tsx,
components/societies/index.ts (SocietyEventsProps re-export unchanged, prop list updated).

OTHER NEW COMPONENTS RE-CHECKED for the same pattern (dynamic-route link that may
not resolve in a fallback path), per team lead's ask:
- SocietyFacts.tsx: no links.
- SocietyAbout.tsx: only links to society.website (external, user-supplied real URL,
  only rendered when present) — not a route we control, no fallback involved.
- SocietyDetailsCallout.tsx: links to /contact (static route, always exists) and a
  mailto: — no dynamic-route risk.
- page.tsx itself: Link to /societies and CTASection to /societies + /contact — both
  static routes, not dynamic, always exist regardless of Sanity state.
No other instance of the pattern found in my new code.
