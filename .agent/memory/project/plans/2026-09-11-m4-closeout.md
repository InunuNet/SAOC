**So this is a pre-existing P1 against `main`, site-wide.** F24 is merely the first consumer that
turns the `null` into a *sentence*. Every other caller turns it into something too — an empty list, a
missing header, a silently absent section — and nobody has audited what.

**FIX BELONGS IN THE SHARED MODULE, AS ITS OWN COMMIT.** Do not patch it inside
`lib/data/show-pages.ts`: that fixes one consumer and leaves the shape intact for the next thirty.
Land it separately from the F24 feature commit so a future reader can find the reasoning.

The distinction the module cannot currently express:
- the query RAN and the document genuinely does not exist -> `null` is the truth, a fallback is honest
- the query COULD NOT RUN (outage, unconfigured client, network) -> **we do not know**, and any
  statement about content is unfounded

Both collapse to `null`. **That collapse is the bug.** Throw on the second, or return a discriminated
result the caller must handle — the same medicine F24 already uses for `ShowPageResult` (an opaque
value a consumer cannot destructure without switching on the discriminant), one layer down.

### The real lesson — better than "eighth instance", and this is the learned.md entry
`A5`/`NF9` was NOT weak. It asserted the absence of try/catch in the function it named, and that was
true. Its unstated assumption was that the function's *dependencies* do not swallow — which no
grep-shaped check on one file can see.

**A property about error propagation cannot be asserted at a single call site. It must be asserted at
the boundary where errors are turned into values.** Write it that way.
