## THE BLOCKER — ROOT CAUSE FOUND 2026-09-10. Do not re-investigate.

**Our seed writes document ids containing a DOT. The dataset's public read grant only covers
ids with NO dot. So the 13 `showPage` documents are invisible to every unauthenticated read.**

Evidence, all reproducible (project `26yfbug4`, dataset `production`, `SANITY_API_TOKEN` from
`.env.local`):

- Dataset `aclMode` is **public**. Documents are genuinely published: raw perspective shows
  **drafts: 0, versions: 0, 13 published**. Ids are bare `showPage.01-national-show-landing` etc.
- Token sees **163** documents; anonymous sees **138**. The 25-document gap is **13 showPage +
  12 Sanity internal `system.*` docs** (always hidden, expected). No other content type is affected.
- `_.groups.public` grants: `{"filter": "_id in path(\"*\")", "permissions": ["read"], "members": ["everyone"]}`.
  **`path("*")` matches a SINGLE path segment.** A dot starts a new segment, so `showPage.17-faq`
  is not matched. `path("**")` would match any depth — the grant does not use it.
- Of 151 content documents: **138 have no dot in the `_id` and every one is anonymously visible;
  13 have a dot and every one is hidden. The dotted set is exactly the showPage set.**
- Project convention everywhere else is a HYPHEN: `showFaq-accessibility-1`, `award-am-saoc`,
  `aboutPage`, `showPageSettings`. Only our seed used a dot.

**THE FIX IS OURS. Do NOT change Sanity permissions and do NOT add a token to the read path.**
`sanity/lib/client.ts` reads anonymously with `useCdn: true` and no token, and that is CORRECT —
21 other types are served through it fine. Passing `SANITY_API_READ_TOKEN` on the published fetch
would turn the routes green while shipping a public site that authenticates to read its own public
pages: the assertion "routes return 200" satisfied without the property "the content is publicly
readable". That is this repo's audited defect class wearing a different hat. The lead has explicitly
vetoed it.

**What to do:** change the id scheme in `scripts/seed-show-pages.ts` from `showPage.<pageKey>` to
`showPage-<pageKey>`, matching the project convention. Re-seed. Verify anonymously — an unauthenticated
`count(*[_type=="showPage"])` against `api.sanity.io` must return 13, not 0. That anonymous count is
the real acceptance test; a 200 from the app is a weaker signal.

**Needs a decision before acting:** the 13 dotted documents already exist in the PRODUCTION dataset.
Creating the dotless ones leaves them orphaned. Deleting them is a destructive write against
production and must be approved by Brad first — do not delete on your own initiative. Orphans are
invisible to the public site either way, so shipping first and cleaning up second is safe.
