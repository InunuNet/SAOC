## 2. H-a: the hub at 768-1023 (decision and evidence)

Cause. `app/(nos)/national-show/nos-theme.css:693-698` (the `@media (max-width: 1023px)` stacked block) gives the hub media `order: 2` and `aspect-ratio: 4 / 3`; the hub hero is `flex-direction: column` there (`:688-690`). Below 768 the later block at `:772-780` overrides to `order: -1; height: 300px; aspect-ratio: auto` (R80 #1). So 768-1023 is the only band where the photo is last.

Decision. In the `max-width: 1023px` hub media rule change `order: 2` to `order: -1` and `aspect-ratio: 4 / 3` to `aspect-ratio: 2 / 1`. Nothing else in the hub rules changes. The `max-width: 767px` block keeps the 300px band, so 390 is untouched; the rule at `:693` is the whole of H-a.
- 2/1 is the inner-page G2 band ratio (`nos-theme.css:739`, `aspect-ratio: 2 / 1`), so the ratio is traced, not chosen.
- Measured result (production build, headless Chromium, live Sanity, #76 head plus exactly these changes): hero 902px at 768 (photo 768x384), 937 at 820, 1057 at 1023 (photo 1023x512, copy block 545px). The ruling expected about 1000 (1190 - 565 + 384 = 1009); the copy block measures 518px at 768 here, not 625, so the 1190 figure came from a different render. The gate cap is 1100 (the ruling's ~1000 plus 10 percent); the lead's 1050 would fail 1023 by 7px. DECISION NEEDED if NOS Design wants a tighter number: it cannot be met by this change alone.
- Image: `NosHero.tsx` serves the hub photo with `sizes="100vw"` from `/images/orchid-dark.jpg` (hero-source-widths.json: 5184 native, q88 variants), so the box (768 / 1023 wide) needs 1536 / 2046 device px at DPR 2, which the variant set covers. No asset change.
- Focal point: `--nos-hero-pos` (68% 50%, hero-photos.ts:27) is already inline on the media element and the stacked rule reads it, so the 2/1 crop keeps the same focal point as 390. A cropped 2/1 view of a 3:2-ish photograph is a new crop of an existing asset; the shots at 768 and 1023 (evidence/) are for NOS Design to eyeball.
- 1024+ is untouched: the desktop rules (`:534-566`) sit outside the 1023 media query.

## 3. LT-1: fold into this PR as one global css change (decision and evidence)

Decision: FOLD. It is a css-only change in `app/(nos)/national-show/nos-theme.css` plus one line in `nos-structure.css`. No tsx edits, so no per-component file list is needed; A4 forbids tsx changes outright.

Why one global rule is possible. The weight is set in one place and wins everywhere:
- `nos-theme.css:340-345`, `.nos-theme :is(h1..h6) { font-weight: 400 }` is unlayered, so it beats every Tailwind weight utility. That is why `components/show/VisitorInfoBlock.tsx:42` (`font-normal min-[889px]:font-light`) and the `font-light` h2s in components/home/* never took effect inside `.nos-theme`.
- `nos-theme.css:349-357`, `.nos-theme h2` forces `font-size: clamp(2rem, 1.2rem + 2.667vw, 3rem)` (unlayered too, so it beats the `text-[clamp(28px,...)]` utilities). Its floor is 2rem = 32px, so EVERY `.nos-theme h2` is 32px or more: 48px at 1280, 32px at 390 (the ruling's own figures). A rule on h2 is therefore exactly "display serif at >= 32px" with no media query.
- Exceptions inside that set are only `.nos-label` (12px Karla, `:363-372`) and `.nos-card-title` (22px, `:375-380`), both of which must stay as they are.
- The other display-size serif headings are the `nos-opsz-fluid` ones (`text-[clamp(28px,3.6vw,44px)]`): `components/nos/SectionHeading.tsx:54` (the TitleTag can be h3), `app/(nos)/national-show/page.tsx:529` (an h2, covered by the h2 rule), `app/(nos)/national-show/not-found.tsx:28` (h1). They cross 32px at 3.6vw = 32, i.e. a 889px viewport, which is exactly the breakpoint the codebase already uses for this (`min-[889px]:font-light` at VisitorInfoBlock.tsx:42). So a `min-width: 889px` step on `.nos-opsz-fluid` is the same rule expressed in css.
- `.nos-theme .nk-head h2` (`nos-structure.css:1511-1519`) pins `font-weight: 400` at 32-39px; it is a one-line change to 300 (it is the only place that restates 400 at a display size).
- Already 300: `.nos-hero-title` (`nos-theme.css:492`), `.nk-masthead h1` (`nos-structure.css:1609`), `.pc-title` (`presenters.css:62`).
- The SAOC site already encodes this exact size rule (`scripts/checks/type-render-check.mjs:5`: >= 32px 300, 20-31.99px 400). The NOS check at `:124` allows [300, 400], so tightening NOS to 300 does not break it.

Rejected: weight as a function of font-size in pure css. Dividing a length by a length inside `calc()` is not baseline, so the rule stays role-based (h2 and the fluid step) and the sweep (A11) is the proof it is complete.

Rule (the dev writes the final text in the existing heading block):
1. Add `font-weight: 300;` INSIDE the existing `.nos-theme h2 { ... }` rule (`nos-theme.css:349-357`). Do not add a separate `h2:not(...)` rule: a (0,2,1) selector would beat the class rules that give the sans eyebrow h2s their own weight (`.nos-index-eyebrow`, `.nos-label`, 600), whereas `.nos-theme h2` is (0,1,1), equal to the base and later in source, and loses to those class rules as it must. A11's sans-300 guard exists because of that trap.
2. Restate `font-weight: 400;` in the two h2 rules that set a sub-32px size and previously inherited 400: `.nos-theme :is(h2, h3).nos-card-title` (22px, `nos-theme.css:375`) and `.nos-theme .nk-attendees-title` (24px, `nos-structure.css:2136`; found by the sweep on /tickets/vip at 390: "VIP Ticket attendees" 24px came out 300).
3. After the heading block add `@media (min-width: 889px) { .nos-theme :is(h1, h2, h3, h4, h5, h6).nos-opsz-fluid { font-weight: 300; } }` (the 28-44px headings reach 32px at 889px).
4. `nos-structure.css` `.nos-theme .nk-head h2`: change `font-weight: 400` to `300`.
Leave the h3-h6 base (`font-weight: 400`) untouched.

Verification already done by the architect: a throwaway worktree at the #76 head with exactly the changes above (H-a plus rules 1-4) was built and both gates run against it. Result: A10 pass; A11 pass with 0 failures (about 178 display-serif and 130 sub-32px serif heading records across 34 planned routes at 1280 and 390; /archive 404s and /media-kit redirects to /admin in the live data, both reported as NOT SWEPT with reasons). A first trial with a separate `h2:not(...)` rule found the `.nk-attendees-title` miss. The worktree and its evidence were removed; the dev regenerates `evidence/` from the real build.

## 11. TK-404 - unknown ticket slug answers 404 (NOS Design P2, folded into A18)

**Symptom.** `/tickets/<unknown>` answers HTTP 200 and the RSC payload carries `NEXT_HTTP_ERROR_FALLBACK;404` plus `noindex`. The rendered page is already the NOS not-found on origin/main c020ad1d (typographic NosHero, no "Find a society"), so what is wrong on main is the status, not the copy.

**Root cause, measured.** `app/(nos)/tickets/[slug]/loading.tsx` (nos-loader-h1). A `loading.tsx` wraps the segment's page in a Suspense boundary, so the shell is flushed with the 200 before the page's `notFound()` (and `generateMetadata`'s) resolves; the error then reaches the client boundary and the status can no longer change. Bisect on a production build of origin/main, one change at a time, each against a freshly started server: unmodified main 200; `loading.tsx` deleted 404; `loading.tsx` restored 200. Not the cause (all still 404 with the loading file removed, and 200 only while it exists): the proxy's `NextResponse.next()` versus a rewrite, `tickets/layout.tsx` and its `generateMetadata`, the group `not-found.tsx`, and `generateMetadata` calling `notFound()`. `/archive/<year>` and an unmatched route answer 404 because they have no `loading.tsx` on the path.

**Verified fix shape (keeps the loader).** A `app/(nos)/tickets/[slug]/layout.tsx` that awaits `params`, reads the ticket type with `sanityFetch(ticketTypeBySlugQuery)` and calls `notFound()` for a missing or hidden-demo product, then returns `children`. A layout renders outside the segment's own `loading.tsx` boundary, so the lookup blocks the shell and the status is 404. Trial on origin/main: unknown slug 404 with the NOS hero, a real slug from the hub still 200. The hidden-demo rule (`isHiddenDemoProduct`, today private to `page.tsx`) must be shared, not copied: extract it with the lookup to `lib/data/ticket-type-lookup.ts` and call it from both the layout and the page, and keep the page's own `notFound()` as the type guard. Deleting `loading.tsx` also fixes the status but loses the nos-loader-h1 loading state, so it is not the fix.

**Files @dev may touch for TK-404** (A4 allowlist): `app/(nos)/tickets/[slug]/page.tsx`, `app/(nos)/tickets/[slug]/layout.tsx`, `app/(nos)/tickets/[slug]/loading.tsx`, `lib/data/ticket-type-lookup.ts` (new). No ticket-specific not-found copy (R7): the copy and CTAs stay Tickets, National Show, Plan your visit.

**Dynamic NOS segments.** origin/main has exactly two under `app/(nos)`: `tickets/[slug]` and `national-show/archive/[year]` (public path `/archive/<year>`; `/national-show/archive/<year>` 308s to it on the nos host). On main `/archive/1900` already answers 404 with the NOS not-found. A18 fails if a directory named `[param]` appears under `app/(nos)` without an entry in `goldens/sweep-routes.json` `dynamicSegments`.

**Gate notes.** The forbidden text is read from `document.body.innerText`, never the raw HTML. `.nos-hero-title` is required on the ticket and archive routes only (it needs the #93 not-found markup, so the branch must carry main's `national-show/not-found.tsx`; the unmatched-route check stays behavioural for either markup). Measured on origin/main: A18 fails 4 of 4 viewports on the ticket route (`responds 404: 200`) and passes with the layout fix.

## 12. TL-1 - the ticket loader reserves the lede (NOS Design P3, folded into H-a with TK-404)

**Ruling.** `app/(nos)/tickets/[slug]/loading.tsx` only: the shell's lede is two `aria-hidden` skeleton bars with no text (R7), each the lede's line-height tall and at the lede's margin, 100% and 70% wide, in the loader's existing bone treatment (`bg-bone`, 2px radius, static: no shimmer, no pulse), no new token. Not a taller min-height (it would shift the 1-line cases and change the hero rhythm). The old shift: at 390@3 the hero grew 427 to 457.84px (+31px) when the page settled.

**How @dev builds it.** Pass the bars as the `lede` of the existing `NosHero` call, so the shell uses the real lede element and its margins. Each bar is `display:block; height:1lh` (the `lh` unit takes the element's own line-height at every breakpoint, so nothing is hard-coded) with the existing `bg-bone` utility; widths `w-full` and `w-[70%]`. No new CSS file, class or token is needed; `loading.tsx` is the only file. Reference build (origin/main plus this loader plus the TK-404 layout) passed A19 twice.

**Gate A19** (`checks/gate-ticket-loader-shift.mjs`, port base +6, goldens `values.json` `tl1`). It enumerates the ticket slugs from the `/tickets` hub links (the hub reads the same Sanity `ticketType` documents the slug page reads; read-only, nothing is written), and for each slug at 1440 and 390@3 drives a held client navigation from `/faq` with a requestAnimationFrame logger (a fresh page per attempt, up to 8 attempts, because the shell can be on screen for one frame once the held request is released). It asserts: two aria-hidden bars, no text, one lede line tall, 100% and 70% wide; the first copy child never moves; no pulse; lede-block shift 0 for a 2-line lede and at most one lede line for every slug. It lists every lede of 3 or more lines at 390 and every slug with no description. The shift is measured on the lede block: the loader is name-agnostic, so a long product name that wraps the title or the last breadcrumb at 390 moves the hero by a name line that no loader can reserve, and that is listed as a FINDING, not folded into the figure.
