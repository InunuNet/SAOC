## 2. Decision (a): a trimmed, verbatim extract, not a whole-file copy

**Measured.** The three `content.md` files hold more than the rendered sections.
- **04** carries Lee-Ann's working notes: "List of Exhibitors / Every nursery has: … / You could even include: …". It also carries the whole blank **Vendor Registration Form** template. Neither is rendered anywhere as page copy.
- **03** carries four paragraphs the section never quotes, and the tail of a sentence it truncates. The source continues "…orchid vendors, offering an exceptional range…"; the body stops at "…orchid vendors."
- **02** carries the "**About**" / "**2027 South African National Orchid Show**" heading lines.

Condition 1 says anything not on the rendered page "comes out or blocks the copy". **So it comes out.**

**The extract rule (mechanical, nothing authored):**
- For each sentence of the section's **seed body**, split exactly as `lib/data/show-pages.ts` does (`(?<=[.!?])\s+`), take the **shortest span of the source** whose normalised text equals the sentence's normalised text.
- Keep the source's own sentence-final `.`/`!`/`?` if one immediately follows.
- Each span is **byte-identical to the source**: no case, quote, punctuation or whitespace change.
- Write the spans in body order, one per paragraph, separated by a single blank line, with one trailing newline.
- 02 has 11 sentences, 03 has 4 and 04 has 3.

**The goldens ARE the extracts.** `goldens/f3-extracts/{02-about-the-national-show,03-what-to-expect,04-south-african-exhibitors}.content.md` were generated by that rule and verified as follows:
- every paragraph is a byte-exact substring of the source;
- the source manifest md5 equals the pinned md5;
- the seed body's sentences map 1:1, in order, onto the paragraphs.

@dev **copies the golden file byte-for-byte**. Re-deriving it is not required, and is not allowed to differ (A2).

**Why a trimmed copy still passes linkage.** `bodyLinkedToSource` needs each normalised body sentence to occur in the normalised source. Each paragraph *is* one body sentence's source span, so every sentence occurs by construction (A10, real `resolveNotice`).

**Rendered-page proof.** Every paragraph also occurs, normalised and with HTML entities decoded, in the public route that renders it today (A3). The route sources are:
- 02: `app/(marketing)/national-show/about/page.tsx`;
- 03: `app/(marketing)/national-show/what-to-expect/page.tsx`;
- 04: `components/vendors/VendorIntro.tsx` on `/national-show/vendors`, plus the gated section on `/national-show/sa-exhibitors`.

Names therefore need no separate scan: a paragraph that is on the public page carries only names the public page already shows.

**Scan result at contract time (on the golden extracts):**
- no credential word, e-mail address, phone number, URL or 6+ digit run;
- every paragraph rendered.

A planted e-mail, phone number and "Password:" line in a fixture made A3 fail on all three rules, plus the rendered check.

### (c) The Sanity write: through `scripts/seed-show-pages.ts`, additions only

**Finding that shapes this.** A plain seed run **cannot** do the job. `decideSectionAction` Rule 1 (`seed-show-pages.ts:141`) returns `skip-council` for any council-supplied section, and never writes it. A plain run would also reconcile every page and `showPageSettings`, which goes beyond "sourcePath on 3 docs".

So the write goes through a **new, separate mode in the same file**. Normal seeding, including Rule 1, is byte-identical: the file diff is **additions only** (A9).

**Exports (pure; A10 unit-tests them):**

```ts
export interface SourceRelink { docId: string; sectionKey: string; from: string; to: string }
export const SOURCE_RELINKS: readonly SourceRelink[]   // exactly the 3 rows below, this order, this key order
export type RelinkDecision =
  | { action: 'relink'; docId: string; sectionKey: string; rev: string; setPath: string; from: string; to: string }
  | { action: 'already-linked'; docId: string; sectionKey: string }
  | { action: 'refuse'; docId: string; sectionKey: string; reason: string };
export function planSourceRelink(
  relink: SourceRelink,
  doc: { _id: string; _rev: string; sections?: Array<{ _key: string; sectionKey: string; provenance?: string | null; sourcePath?: string | null; body?: unknown }> } | null,
  isLinked: (sourcePath: string, body: unknown) => boolean,
): RelinkDecision
export function relinkSetPayload(d: Extract<RelinkDecision, { action: 'relink' }>): Record<string, string> // === { [d.setPath]: d.to }
```

`SOURCE_RELINKS` (`docId`, `sectionKey`, `from`, `to`):
- `showPage-02-about-the-national-show`, `overview`, `content/drive-source/National Show/2. About/2.1 About - 2027 National Show/v1.0/content.md` → `content/drive-recovered/02-about-the-national-show/about/content.md`
- `showPage-03-what-to-expect`, `overview`, `content/drive-source/National Show/3. What to expect/3.1 Info - What to Expect/v1.0/content.md` → `content/drive-recovered/03-what-to-expect/what-to-expect/content.md`
- `showPage-04-south-african-exhibitors`, `overview`, `content/drive-source/National Show/4. South African Exhibitors/1.1 Exhibitors - South African Exhibitors/v1.0/content.md` → `content/drive-recovered/04-south-african-exhibitors/sa-exhibitors/content.md`

**`planSourceRelink` order of checks:**
1. Doc missing → refuse.
2. `_id` ≠ `docId` → refuse.
3. Not exactly one section with `sectionKey` → refuse.
4. `provenance !== 'council-supplied'` → refuse.
5. `sourcePath === to` → `already-linked` if `isLinked(to, body)`, else refuse.
6. `sourcePath !== from` → refuse.
7. `!isLinked(to, body)` → refuse. This runs on the **live** body, so an edit made in Studio blocks the relink.
8. Otherwise relink, with `setPath = sections[_key=="<existing _key>"].sourcePath` and `rev = doc._rev`.

**CLI:** `node --import tsx/esm scripts/seed-show-pages.ts --relink-sources [--apply]`, run from the worktree root (`pnpm --dir .tmp/sandbox/provenance exec …`).
- **Dispatch:** an inserted first statement in `main()` after `getClient()` that returns early. It never calls `seedShowPageSettings` or `reconcilePage`.
- **Linkage oracle:** `isLinked` = `(p, b) => resolveNotice({ provenance: 'council-supplied', sourcePath: p, body: b }) === null`. It is imported **dynamically** inside the relink path, as `await import('@/lib/data/show-pages.ts')`, so module import stays credential-free.
- **Docs read:** `client.getDocument(docId)` for the three **hyphen** ids only. The legacy `showPage.<pageKey>` dot-id duplicates are not read and not written.
- **Output** (one line per relink, exactly these prefixes):
  - `RELINK <docId>/<sectionKey>: <from> -> <to> (rev <rev>)`
  - `ALREADY <docId>/<sectionKey>: <to>`
  - `REFUSE <docId>/<sectionKey>: <reason>`
- **Dry run** (no `--apply`) ends with the line `DRY RUN — no write issued`.
- **All-or-nothing preflight:** any REFUSE means no write at all, and exit 1.
- **`--apply`**, per relink: `client.patch(docId).ifRevisionId(rev).set(relinkSetPayload(d)).commit({ autoGenerateArrayKeys: false })`, then `APPLIED <docId>/<sectionKey>: <to>`.
  - It does **not** touch `seedHash`, body, heading, provenance or any other field.
  - A rejected commit (revision moved) prints `REFUSE … revision changed` and exits 1.

**Write sequence.** Each step is a gate. The logs go to `.tmp/sandbox/provenance-relink/`.
1. Offline assertions A1–A10 green.
2. **Record before** (read-only):
   `node .tmp/sandbox/provenance/contracts/checks/nos-provenance-fix/check-relink-live.mjs snapshot .tmp/sandbox/provenance .tmp/sandbox/provenance-relink/before.json`
   This snapshots all showPage docs in the raw perspective and refuses unless the three targets still hold their `from` paths. Copy its three `BEFORE` lines into `spec.md` §10.
3. **Dry run:**
   `pnpm --dir .tmp/sandbox/provenance exec node --import tsx/esm scripts/seed-show-pages.ts --relink-sources > .tmp/sandbox/provenance-relink/dry-run.log 2>&1`
   This must give 3 × `RELINK`, 0 × `REFUSE` (A11).
4. **Write sourcePath only:** the same command with `--apply`, to `apply.log`. This must give 3 × `APPLIED` (A12).
5. **Record after:** `check-relink-live.mjs verify …/before.json`. It writes `after.json` and passes only if every showPage doc (26 today: 13 hyphen and 13 dot-id) deep-equals its snapshot except `_rev`/`_updatedAt` and the three pinned sourcePaths (A13). Copy its three before→after lines into `spec.md` §10.
6. **Live notice matrix:** `check-notice-matrix.ts --live` (A14).

**Credentials.** `.tmp/sandbox/provenance/.env.local` exists and is gitignored. It is a copy of the trace-fix worktree's, and it holds the write token the seed reads and the read token `check-relink-live` reads. Nothing prints a value.

## 5. Decision (d): the condition-3 assertions

`contracts/checks/nos-provenance-fix/check-notice-matrix.ts` runs **every section of every showPage** through the real `resolveNotice()` (and so `classifySection`). It does this for the seed corpus (A5) and for the published dataset read anonymously, the same view the site gets (A14). It compares each notice kind with the pinned matrix in `f3-notice-matrix.md`.

**It also enforces the rule directly:**
- a recovered `council-supplied` section has **no** notice;
- a recovered `council-draft` section has the **draft** notice;
- every `placeholder-ai` section keeps the **placeholder** notice.

**Six negative cases on real data** (04/overview):
1. the old gitignored drive-source path → placeholder;
2. one invented sentence appended → placeholder;
3. a linked body with provenance `placeholder-ai` → placeholder;
4. `council-supplied` with no sourcePath → placeholder;
5. a linked body as `council-draft` → draft, never clean;
6. another page's recovered file → placeholder.

**Gated routes.** It asserts each of the six gated routes still renders its pageKey through `loadShowPageOrFallback`. The routes are international-guests, programme, sa-exhibitors, sponsors, symposium and wosa-conference.

**Clean clone.** It refuses to run (exit 2) if `content/drive-source/` exists in the worktree, because a pass there would not reflect beta.
